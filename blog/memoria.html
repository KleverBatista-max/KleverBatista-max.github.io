La memoria compartida

Un asistente de IA olvida todo al cerrar la conversación. Yo me cansé de repetirle quién soy y cómo trabajo, así que le di memoria con lo más simple que existe: archivos de texto.

El problema

Cada sesión empezaba de cero: las mismas explicaciones, los mismos errores. Y yo trabajo en varias computadoras, así que la memoria tenía que viajar conmigo.

Antes de esto: mi primera IA

Mi primera IA fue ChatGPT y la usé durante dos años: de julio de 2024 a septiembre de 2026 fueron 876 conversaciones y casi 29 millones de caracteres. Ahí aprendí muchísimo, y también aprendí el problema que hoy resuelve esta memoria: cada conversación empezaba de cero. Las decisiones quedaban enterradas en chats larguísimos, el código que funcionaba solo existía dentro de una conversación y, cuando se me dañó una computadora sin copia, lo único que me quedaba era ese historial.

Pedí la exportación de la cuenta, la ordené por proyectos y rescaté lo que valía la pena: la historia de la casa solar, el BliKVM y una primera versión de mi sistema financiero. Los chats pasaron de ser un cementerio a ser una fuente. Y me confirmaron la idea de esta página: lo que no está escrito en un lugar que yo controlo, se pierde.

Cómo funciona

  • Una carpeta de archivos de texto. Cada recuerdo es un archivo con un solo dato: quién soy, cómo prefiero que me trabaje, el estado de un proyecto o dónde encontrar algo.
  • Un índice. Un archivo corto lista todos los recuerdos con una línea cada uno, y el asistente lo lee al empezar cada sesión.
  • Cuatro tipos: sobre mí, correcciones y preferencias, proyectos en curso y referencias a dónde buscar.
  • Sincronizada con Git. La carpeta es un repositorio privado y unos ganchos la sincronizan entre mi Mac y mi PC con Windows, así que las dos computadoras recuerdan lo mismo.

Reglas que me pusieron a salvo

  • Nunca guardar contraseñas ni claves en la memoria.
  • Un recuerdo se verifica antes de usarlo. Si dice que existe un archivo o una función, se comprueba que siga existiendo.
  • Lo equivocado se borra. Una memoria incorrecta es peor que ninguna.
  • No se guarda lo que ya está en el código ni en el historial de Git.

Por qué me gusta

Es la misma pereza productiva de siempre: explicar algo una vez y que no haya que volver a hacerlo. Y por ser texto plano, la puedo leer, corregir y respaldar como cualquier otro archivo. Esta misma página y las historias de los proyectos salieron en buena parte de ella. El repositorio es privado porque guarda datos míos.

The shared memory

An AI assistant forgets everything when the conversation closes. I got tired of repeating who I am and how I work, so I gave it memory with the simplest thing there is: text files.

The problem

Every session started from zero: the same explanations, the same mistakes. And I work on several computers, so the memory had to travel with me.

Before this: my first AI

My first AI was ChatGPT and I used it for two years: from July 2024 to September 2026 it came to 876 conversations and almost 29 million characters. I learned a great deal there, and I also learned the problem this memory solves today: every conversation started from zero. Decisions got buried in endless chats, the code that worked only existed inside a conversation and, when a computer of mine died without a backup, that history was all I had left.

I asked for an export of the account, sorted it by project and rescued what was worth keeping: the story of the solar house, the BliKVM and a first version of my financial system. The chats went from being a graveyard to being a source. And they confirmed the idea behind this page: what isn't written down somewhere I control gets lost.

How it works

  • A folder of text files. Each memory is a file with a single fact: who I am, how I prefer to be worked with, the state of a project or where to find something.
  • An index. A short file lists every memory with one line each, and the assistant reads it at the start of every session.
  • Four types: about me, corrections and preferences, ongoing projects and pointers to where to look.
  • Synced with Git. The folder is a private repository and a few hooks sync it between my Mac and my Windows PC, so both computers remember the same things.

Rules that kept me safe

  • Never store passwords or keys in the memory.
  • A memory is verified before it is used. If it says a file or function exists, check that it still does.
  • Wrong things get deleted. An incorrect memory is worse than none.
  • Don't store what is already in the code or in the Git history.

Why I like it

It's the same productive laziness as always: explain something once and never again. And being plain text, I can read, fix and back it up like any other file. This very site and the project stories came largely out of it. The repository is private because it holds personal data.
